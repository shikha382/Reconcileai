# Demo Failure Plan (Milestone 17)

Every point of live-judging failure, its detection, impact, recovery, fallback, and what to tell the judge. The demo must never depend on a live external service unless explicitly required — confirmed true here: fixture mode is the default, `MockAIProvider` is the default, and no step in `docs/three-minute-demo.md` requires network access to Razorpay or an LLM vendor.

| # | Failure | Detection | Impact | Recovery | Fallback | What to tell the judge |
|---|---|---|---|---|---|---|
| 1 | Backend (`uvicorn`) fails to start | Terminal shows a traceback instead of "Uvicorn running on..." | Frontend shows a connection error on every page | Check the terminal for the actual error (usually a port already in use or a stale `reconcileai.db` lock); `netstat`/kill the conflicting process, restart | `python scripts/run_reconciliation.py` — the entire pipeline in terminal output, zero UI/API dependency | "The API didn't come up cleanly — let me show you the same result the terminal-only way, which is the same code path." |
| 2 | Frontend (`npm run dev`) fails to start | Browser shows "This site can't be reached" | No UI at all | Confirm `node_modules` installed (`npm install`), restart `npm run dev` | Same as #1 — terminal run needs no frontend | Same framing as #1 |
| 3 | Fixture data fails to load | A 500 or empty-state screen on `POST /runs` | Run cannot start | Confirm `data/synthetic/seeds/*.json` exist and are unmodified; re-clone/re-check the dataset directory | `scripts/run_reconciliation.py --dataset data/synthetic/seeds` explicitly | "Let me point the run at the known-good dataset path directly." |
| 4 | Pipeline throws mid-run | `PipelineRunResult.status == "failed"`, or an unhandled exception in the terminal | The specific run shows no results | Restart with a fresh `POST /runs` (or terminal script) — this project's own fail-safe design marks a failed run `"failed"`, never a false partial "completed" | Re-run; if it fails twice, fall back to a previously-known-good screenshot narrative while debugging live (last resort) | "The system just proved its own fail-safe design — a failure here shows as an honest failed run, not a silently wrong result. Let me re-run it." |
| 5 | AI provider (MockAIProvider) misbehaves | Extremely unlikely — deterministic, no network — but if the AI config env vars are accidentally pointed at a real, uncredentialed provider | Investigation calls fail/timeout for the 74 AI-routed cases | Confirm `AI_PROVIDER`/`LLM_PROVIDER` env vars are unset or explicitly `mock` before the demo starts | Restart the backend process with env vars cleared | "That's not the mode we run the demo in — let me restart with the demo's own configuration." |
| 6 | Razorpay adapter (`live` mode) fails | N/A for the demo — fixture mode is the only mode the demo ever uses | None, if configuration is correct | Confirm `PROVIDER_MODE` is unset or `fixture` before the demo | Same as #5 | "We never demo against live Razorpay — that mode exists in code but isn't exercised here, by design." |
| 7 | API (FastAPI routes) return unexpected errors | A structured `{"error": {...}}` body instead of data | The specific page/action fails | The structured error itself names the `request_id` — check backend logs for that ID | Retry the action; if persistent, fall back to the terminal script | "Even our failures are structured, not a raw crash — you can see the request ID we'd use to trace this." |
| 8 | Browser issues (crash, extension interference, wrong URL) | Blank page, console errors | Demo visually stalls | Open a fresh private/incognito window, navigate to `http://localhost:5173` directly | Same terminal fallback | "Let me open a clean browser window." |
| 9 | Database (SQLite) file locked or corrupted | A 500 on any DB-touching route, or a "database is locked" error in logs | Entire backend degraded | Stop `uvicorn`, delete `backend/reconcileai.db`, restart (documented reset — `docs/demo-runbook.md`) | Same terminal fallback while resetting | "This is our documented reset step — a fresh demo state in two commands, nothing exotic." |
| 10 | Network unavailable in the judging room | Frontend/backend both run on `localhost` — **should be unaffected**, since nothing in the demo path calls an external network | None expected | Confirm beforehand that `127.0.0.1`/`localhost` traffic isn't blocked by room Wi-Fi/firewall policy (rare but possible on some corporate networks) | Terminal script needs no network at all | "Everything you're seeing is running entirely on this machine — no network dependency." |
| 11 | Environment variables misconfigured (stale `AI_PROVIDER`, `PROVIDER_MODE`, DB path) | Unexpected behavior not matching the rehearsed script | Confusing, hard-to-diagnose deviation | Before the session: explicitly unset or set `AI_PROVIDER`/`PROVIDER_MODE`/`AI_API_KEY` to the demo's known-good values in the terminal that will launch `uvicorn` | Restart with a clean shell / explicit env vars | "Let me restart with our documented demo configuration." |

## Pre-judging checklist (do this once, before the room opens)

1. Fresh terminal, confirm `git`/repo state is what you intend to show (see `docs/final-winning-audit.md` §0 — resolve this before judging, not during).
2. Delete any stale `backend/reconcileai.db` for a clean run.
3. Confirm env: no `PROVIDER_MODE=live`, no `AI_PROVIDER` pointed at a real, uncredentialed vendor.
4. Start backend (`uvicorn app.main:app --host 127.0.0.1 --port 8000`), confirm it logs "Uvicorn running."
5. Start frontend (`npm run dev`), confirm `http://localhost:5173` loads.
6. Do one full dry run of the 3-minute script end to end, including starting a fresh run via the UI.
7. Have `python scripts/run_reconciliation.py` ready in a second terminal tab as the standing fallback — untouched, not started, just ready to run on demand.

**The demo must never depend on live external services** — confirmed: fixture mode + MockAIProvider are the defaults, and no step above requires Razorpay or an LLM vendor to be reachable.
